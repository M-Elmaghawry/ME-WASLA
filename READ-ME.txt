- Complete English translations.
- Proper LTR layouts.

## Language Switcher
Add an AR / EN language switcher in the header and footer.

Switching languages should preserve the equivalent current page whenever possible.

Do not mix Arabic and English within the same interface except for intentional product names and technical terminology.

Store all content in structured localization dictionaries.

Use these localized URL structures:

- `/ar/`
- `/en/`
- `/ar/about`
- `/en/about`
- `/ar/features`
- `/en/features`
- `/ar/pricing`
- `/en/pricing`
Continue the same structure for all other pages.

Redirect `/` to the Arabic homepage.

Add proper hreflang tags, canonical URLs, localized meta descriptions, and Open Graph tags.

# GitHub Pages Deployment

The website is deployed by `.github/workflows/deploy.yml` when changes are pushed to `main` or `master`. The workflow also supports manual runs from the GitHub Actions tab.

To enable deployment:

1. Push the project to a GitHub repository.
2. Open **Settings → Pages** and set **Build and deployment → Source** to **GitHub Actions**.
3. Open the **Actions** tab and confirm that **Deploy to GitHub Pages** completes successfully.
4. Open the Pages URL shown in the deployment job. Direct links to localized pages are supported.

The workflow configures the correct base path for both project repositories and `username.github.io` repositories. For local development, run `npm install` once and then `npm run dev`. To build locally, run `npm run build`.
